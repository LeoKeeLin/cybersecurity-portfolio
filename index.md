## Learning Journey

### From Software Development to Cybersecurity

My cybersecurity learning journey builds upon my experience in software development. Working with web applications, databases, and server environments has helped me understand how software systems are designed, deployed, and maintained. As I explored cybersecurity, I became increasingly interested in understanding how these systems can be attacked and, more importantly, how they can be protected.

I am currently strengthening my cybersecurity knowledge through academic studies, technical training, and hands-on laboratory exercises. My learning focuses on building a solid foundation in networking, Linux administration, and security testing.

### Learning Through Practical Experience

Two important learning experiences were setting up an isolated virtual security laboratory and performing network reconnaissance using Nmap.

Building the laboratory helped me understand network isolation, IP addressing, and connectivity testing. Using Nmap to identify open ports and running services helped me understand how network reconnaissance supports security assessments and why exposed services require further investigation.

These experiences also changed how I approach technical problems. I now pay more attention to understanding the purpose of each step, checking whether the results make sense, and recording what I learn so I can apply it in future exercises.

### Applying Programming Skills to Cybersecurity

Developing a network scanning tool using Python and Scapy allowed me to apply my software development experience to cybersecurity. This project helped me explore how network scanning tools work and strengthened my understanding of network protocols and port scanning techniques. It also encouraged me to approach cybersecurity from both a developer's and a security practitioner's perspective.

### Challenges and Lessons Learned

During my Nmap reconnaissance exercise, I encountered a service-version scan that was taking longer than expected. I investigated the scanning process and identified DNS resolution as a possible cause of the delay. By adding the `-n` option to disable DNS resolution, I was able to complete the scan more efficiently.

This experience taught me the importance of understanding command options, troubleshooting unexpected behaviour, and verifying results rather than simply relying on tools to work as expected.

### Areas for Improvement

One area I still find challenging is interpreting network scanning results and determining their security implications. Although I can identify open ports and running services using Nmap, understanding whether these findings represent actual vulnerabilities requires further investigation.

I would like to improve my ability to analyse security findings, assess potential risks, and recommend appropriate security measures.

### Future Learning Goals

I aim to reach 2,500 points on TryHackMe by 31 December 2026, focusing on network security and penetration testing.

I also plan to complete five Cisco Networking Academy courses by 31 January 2027: CyberOps Associate, Introduction to Networks, Switching, Routing, and Wireless Essentials, Enterprise Networking, Security, and Automation, and Network Security.
